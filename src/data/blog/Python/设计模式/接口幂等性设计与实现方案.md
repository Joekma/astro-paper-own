## 概述

幂等性是指接口被重复调用时，结果应该保持一致。在分布式系统中，网络超时、重试等场景经常导致接口被重复调用，幂等性设计变得尤为重要。

## HTTP 方法幂等性

| 方法 | 幂等性 | 说明 |
|------|--------|------|
| **GET** | 幂等 | 查询操作，多次调用结果相同 |
| **POST** | 非幂等 | 创建操作，每次调用创建新资源 |
| **PUT** | 幂等 | 更新操作，多次调用结果相同 |
| **DELETE** | 幂等 | 删除操作，删除已删除的资源无影响 |
| **PATCH** | 非幂等 | 部分更新，语义可能非幂等 |

## 幂等性场景

### 支付场景

```python
# 问题：支付结果回调可能重复发送
# 解决：使用支付流水号做幂等

def handle_payment_notify(data):
    order_id = data['order_id']
    transaction_id = data['transaction_id']

    # 检查是否已处理
    if redis.exists(f'payment:processed:{transaction_id}'):
        return '已处理'

    # 处理支付
    process_payment(order_id, data)

    # 标记已处理
    redis.setex(f'payment:processed:{transaction_id}', 86400, '1')
    return '成功'
```

### 订单创建

```python
# 问题：前端重试可能创建重复订单
# 解决：使用订单号幂等

def create_order(request_id, order_data):
    # 检查是否已创建
    existing = db.query("SELECT * FROM orders WHERE request_id = ?", request_id)
    if existing:
        return existing

    # 创建订单
    order = db.insert("INSERT INTO orders ...", order_data)
    return order
```

### 消息消费

```python
# 问题：消息可能被重复消费
# 解决：消费前检查消息 ID

def consume_message(msg):
    msg_id = msg['id']

    # 检查是否已消费
    if redis.setnx(f'consumer:processed:{msg_id}', '1'):
        redis.expire(f'consumer:processed:{msg_id}', 86400)
        process_message(msg)
    else:
        logger.info(f"消息 {msg_id} 已处理，跳过")
```

## 实现方案

### 方案一：Token 机制

使用唯一 Token 标识请求：

```python
from flask import Flask, request, jsonify
import redis
import uuid

app = Flask(__name__)
r = redis.Redis()

@app.route('/submit', methods=['POST'])
def submit():
    token = request.json.get('token')

    # 检查 Token 是否已使用
    if r.exists(f'token:used:{token}'):
        return jsonify({'error': '重复请求'}), 409

    # 标记 Token 已使用
    r.setex(f'token:used:{token}', 3600, '1')

    # 处理业务
    result = process_business(request.json)
    return jsonify(result)

# 生成 Token
def generate_token():
    return str(uuid.uuid4())
```

### 方案二：唯一索引

利用数据库唯一索引防止重复：

```sql
-- 创建订单表
CREATE TABLE orders (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    request_id VARCHAR(64) UNIQUE NOT NULL,
    user_id BIGINT,
    amount DECIMAL(10,2),
    status VARCHAR(20),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 插入订单
INSERT INTO orders (request_id, user_id, amount, status)
VALUES (:request_id, :user_id, :amount, 'pending')
ON DUPLICATE KEY UPDATE id=id;
```

### 方案四：乐观锁

使用版本号防止并发更新：

```sql
-- 查询时获取版本号
SELECT id, amount, version FROM orders WHERE id = ?;

-- 更新时检查版本号
UPDATE orders
SET amount = ?, version = version + 1
WHERE id = ? AND version = ?;
```

```python
def update_order(order_id, new_amount):
    order = db.query("SELECT * FROM orders WHERE id = ?", order_id)
    affected = db.execute(
        "UPDATE orders SET amount = ?, version = version + 1 WHERE id = ? AND version = ?",
        (new_amount, order_id, order.version)
    )
    if affected == 0:
        raise ConcurrentUpdateException('并发更新，请重试')
```

### 方案五：Redis 去重

使用 Redis 实现高效去重：

```python
class IdempotencyService:
    def __init__(self, redis_client):
        self.redis = redis_client

    def is_duplicate(self, key, ttl=3600):
        return self.redis.exists(key)

    def mark_processed(self, key, ttl=3600):
        self.redis.setex(key, ttl, '1')

    def check_and_process(self, key, func, ttl=3600):
        if self.is_duplicate(key):
            return None, True

        result = func()
        self.mark_processed(key, ttl)
        return result, False
```

### 方案六：分布式锁

```python
import redis

class DistributedLock:
    def __init__(self, redis_client):
        self.redis = redis_client

    def acquire(self, key, timeout=10):
        return self.redis.set(f'lock:{key}', '1', nx=True, ex=timeout)

    def release(self, key):
        self.redis.delete(f'lock:{key}')

def process_with_lock(order_id):
    lock = DistributedLock(redis_client)

    if not lock.acquire(f'order:{order_id}', timeout=30):
        raise ConcurrentException('请求正在处理中')

    try:
        return do_process(order_id)
    finally:
        lock.release(f'order:{order_id}')
```

## 高并发场景

### Redis + Lua 原子操作

```lua
-- 幂等检查原子脚本
local key = KEYS[1]
local ttl = tonumber(ARGV[1])
local result = redis.call('SETNX', key, '1')
if result == 1 then
    redis.call('EXPIRE', key, ttl)
    return 1
else
    return 0
end
```

```python
def check_and_set(key, ttl=3600):
    script = """
    local result = redis.call('SETNX', KEYS[1], '1')
    if result == 1 then
        redis.call('EXPIRE', KEYS[1], ARGV[1])
        return 1
    else
        return 0
    end
    """
    return redis.eval(script, 1, key, ttl) == 1
```

### 多级缓存

```
┌─────────┐    ┌─────────┐    ┌─────────┐
│  业务层 │ ──▶ │  Redis  │ ──▶ │  数据库 │
└─────────┘    └─────────┘    └─────────┘
```

```python
def query_with_cache(order_id):
    cache_key = f'order:{order_id}'

    # 先查缓存
    cached = redis.get(cache_key)
    if cached:
        return json.loads(cached)

    # 查数据库
    order = db.query("SELECT * FROM orders WHERE id = ?", order_id)

    # 写入缓存
    if order:
        redis.setex(cache_key, 3600, json.dumps(order))

    return order
```

## 实现建议

### 接口设计

1. **POST 请求必须幂等**：创建类接口必须支持幂等
2. **返回唯一标识**：每次请求返回业务 ID
3. **明确错误码**：区分业务错误和系统错误
4. **日志追踪**：记录请求 ID 便于排查

### 数据库设计

1. **业务 ID 唯一索引**：防止重复插入
2. **版本号字段**：支持乐观锁
3. **状态字段**：状态机控制
4. **创建/更新时间**：审计追踪

### 代码规范

```python
# 好的设计
@idempotent(key='request_id', ttl=3600)
def create_order(request_id, data):
    pass

# 或显式处理
def handle_payment(notify):
    if is_duplicate(notify.transaction_id):
        return 'ignored'
    return do_payment(notify)
```

## 小结

幂等性设计要点：

- **唯一标识**：每笔业务使用唯一 ID
- **去重检查**：处理前检查是否已处理
- **状态机**：合理的状态流转控制
- **乐观锁**：并发更新的保护机制
- **组合方案**：多种方案结合使用
