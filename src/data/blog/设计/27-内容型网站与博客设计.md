## 前置知识与学习目标

**前置知识：** 理解信息架构、排版、响应式和页面状态。

**本篇唯一核心问题：** 怎样让内容型网站同时支持连续阅读、信息发现和克制转化？

读完后，你应该能够：能组织文章页、内容列表、目录、搜索和相关推荐，并保护阅读主线。本篇沿用“跨端客户工单管理 SaaS”，核心对象统一为 `ticket`、`customer`、`assignee`、`status`、`priority` 与 `permission`。

上一章已经解决“怎样在商品、结账、支付和失败恢复之间减少不确定性与中断”的问题；本篇把它作为输入，不再重复完整解释。

## 从真实问题出发

技术文章被侧栏、浮层和多个 CTA 包围，读者在移动端无法稳定阅读代码和图表。

先不要急着选择组件或颜色。应先写清楚当前用户、对象、触发条件、成功结果和失败后仍需保留的上下文，再判断界面应该表达什么。

## 核心机制

内容站的核心任务是理解与发现。文章页提供标题、摘要、正文层级、上下文导航和来源；列表与搜索帮助定位；相关推荐依据主题与学习依赖，而不是只追求点击。

### 1. 正文宽度、字号、行高和代码横向滚动按长期阅读优化

正文宽度、字号、行高和代码横向滚动按长期阅读优化。它先固定主路径和优先级，后续布局不得反过来改变业务判断。验收时要用真实任务观察用户能否找到下一步。

### 2. 目录反映真实标题层级，并在跳转后保留清晰焦点

目录反映真实标题层级，并在跳转后保留清晰焦点。它把抽象原则转换成可见结构。验收时应检查对象、标签、状态和操作是否逐项对应，而不是凭整体观感打分。

### 3. 搜索结果展示命中语境、类型和更新时间

搜索结果展示命中语境、类型和更新时间。它负责异常与边界，必须使用空数据、慢请求、权限差异或冲突数据复测，不能只验证理想状态。

### 4. 转化入口放在自然决策点，不能遮挡内容或伪装成正文

转化入口放在自然决策点，不能遮挡内容或伪装成正文。它防止局部页面自行发明规则。跨端、跨主题或跨角色检查时，语义保持一致，呈现方式才允许重组。

## 关键角色、数据与状态

| 项目     | 在本篇中的含义                                                                       |
| -------- | ------------------------------------------------------------------------------------ |
| 输入     | 输入是内容模型与读者任务                                                             |
| 业务对象 | `ticket` 是工单，`customer` 是客户，`assignee` 是当前负责人                          |
| 约束     | `permission` 决定可执行动作；`priority` 影响排序，不直接替代业务状态                 |
| 状态主线 | `draft → submitted → processing → resolved → closed`，只有满足权限和前置条件才能转换 |
| 输出     | 是可阅读、可定位、可继续学习的页面。                                                 |

输入是内容模型与读者任务；中间状态是文章结构、发现路径和阅读进度；输出是可阅读、可定位、可继续学习的页面。

## 最小实践：贯穿工单案例

本系列文章在页头说明前置知识，正文目录只展示 H2/H3，页尾根据 knowledge-map 指向下一篇，而不是随机推荐。

执行时使用下面的决策记录，避免示例只有结果而没有中间状态：

```text
输入：角色、ticket、当前 status、permission、终端与网络状态
检查：核心任务、业务规则、可见反馈、失败恢复、跨端差异
中间状态：记录用户动作、系统判断、状态变化和仍被保留的数据
输出：可验证的界面方案、实现约束与验收证据
失败边界：权限不足、空数据、超时、冲突、长文案和窄屏
```

这里的 `status` 表示业务状态；请求的 loading/error 是界面请求状态，两者不能混为一个字段。示例中的数值与规则只用于教学，接入真实项目时必须由产品规则、接口契约和数据字典确认。

## 常见误区

- **目录层级与正文不一致：** 这会让界面结论失去可验证依据；应回到输入、状态和恢复路径重新检查。
- **移动端复制桌面双栏：** 这会让界面结论失去可验证依据；应回到输入、状态和恢复路径重新检查。
- **用无限滚动破坏文章定位和返回：** 这会让界面结论失去可验证依据；应回到输入、状态和恢复路径重新检查。

## 适用边界与不适用场景

- 短营销内容可采用更强转化结构，但不能冒充深度教程。
- 大型知识库还需版本、权限、搜索相关性和内容治理。

如果当前任务没有多对象关系、状态变化或失败恢复，不要为了套用本章而制造额外组件和流程。复杂度必须来自真实认知问题。
