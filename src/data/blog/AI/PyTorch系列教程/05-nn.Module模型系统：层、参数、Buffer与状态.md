## 本篇要解决的问题

为什么把 `nn.Linear` 放进普通 Python 列表后，优化器可能看不到它？模型中哪些状态应该训练，哪些状态只需要跟随设备和 Checkpoint？`model.eval()` 到底改变了什么，为什么它不能替代关闭梯度？

`nn.Module` 的价值不是少写几个矩阵乘法，而是建立一套状态协议：**可训练参数、非训练 Buffer、子模块、设备迁移、模式切换和序列化都能沿同一棵模块树传播**。

### 前置知识

理解 Tensor、Autograd、叶子张量和梯度累积，能够读懂基本 Python 类。

## 从函数升级为模型

前一篇的线性模型由散落的 `w`、`b` 组成。真正项目需要把参数、结构与前向规则放在一起：

```python
import torch
import torch.nn as nn


class FashionMLP(nn.Module):
    def __init__(self, hidden_size: int = 256, dropout: float = 0.1):
        super().__init__()
        self.flatten = nn.Flatten(start_dim=1)
        self.classifier = nn.Sequential(
            nn.Linear(28 * 28, hidden_size),
            nn.ReLU(),
            nn.Dropout(dropout),
            nn.Linear(hidden_size, 10),
        )

    def forward(self, images: torch.Tensor) -> torch.Tensor:
        if images.ndim != 4 or images.shape[1:] != (1, 28, 28):
            raise ValueError(
                f"expected [B,1,28,28], got {tuple(images.shape)}"
            )

        features = self.flatten(images)
        return self.classifier(features)
```

模型接口为：

```text
images [B,1,28,28] → logits [B,10]
```

实例化并调用时应写 `model(images)`，不要直接调用 `model.forward(images)`：

```python
model = FashionMLP()
images = torch.randn(8, 1, 28, 28)
logits = model(images)

assert logits.shape == (8, 10)
```

`Module.__call__` 会在内部执行 Hook、Autocast 等框架逻辑，再调用 `forward`。绕过 `__call__` 会让这些机制失效。

## Module 如何注册状态

把子模块赋给 `self` 属性时，`nn.Module.__setattr__` 会自动注册它：

```python
model = FashionMLP()

for name, module in model.named_modules():
    print(name, type(module).__name__)
```

输出包含根模块、`flatten`、`classifier` 以及 Sequential 内的各层。Parameter 也会沿树递归收集：

```python
for name, parameter in model.named_parameters():
    print(name, tuple(parameter.shape), parameter.requires_grad)
```

普通 Python 容器不会自动注册其中的 Module：

```python
class WrongStack(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = [nn.Linear(16, 16) for _ in range(3)]
```

`model.parameters()`、`model.to(device)` 和 `state_dict()` 都不会递归识别这个列表里的层。应该改为：

```python
class CorrectStack(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.ModuleList(
            [nn.Linear(16, 16) for _ in range(3)]
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        for layer in self.layers:
            x = torch.relu(layer(x))
        return x
```

需要按键组织时使用 `nn.ModuleDict`；需要把层依次执行时使用 `nn.Sequential`。`ModuleList` 只负责注册，不会自动定义执行顺序。

## Parameter 与普通 Tensor

`nn.Linear` 内部的 `weight`、`bias` 是 `nn.Parameter`。Parameter 是默认要求梯度的 Tensor 子类，被赋给 Module 属性时会注册：

```python
class Scale(nn.Module):
    def __init__(self):
        super().__init__()
        self.log_scale = nn.Parameter(torch.zeros(()))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return x * self.log_scale.exp()
```

不要在 `forward` 中重新创建 Parameter。那会让每次调用产生新状态，优化器仍持有旧参数引用：

```python
# 错误示意
def forward(self, x):
    self.weight = nn.Parameter(torch.randn(x.shape[-1], 10))
    return x @ self.weight
```

参数 Shape 应在初始化时由配置确定；若确实需要延迟推断输入维度，可以使用 PyTorch 提供的 Lazy 模块，并明确其初始化时机。

## Buffer：持久但不训练的状态

模型还可能有需要随设备移动、随 `state_dict` 保存，却不参与梯度更新的 Tensor，例如 BatchNorm 的运行统计、位置索引或固定归一化常量。使用 `register_buffer`：

```python
class NormalizeAndClassify(nn.Module):
    def __init__(self):
        super().__init__()
        self.register_buffer(
            "mean", torch.tensor([0.2860]).reshape(1, 1, 1, 1)
        )
        self.register_buffer(
            "std", torch.tensor([0.3530]).reshape(1, 1, 1, 1)
        )
        self.model = FashionMLP()

    def forward(self, images: torch.Tensor) -> torch.Tensor:
        normalized = (images - self.mean) / self.std
        return self.model(normalized)
```

`mean` 和 `std` 不会出现在 `named_parameters()`，但默认会出现在 `state_dict()`，并随 `model.to("cuda")` 一起移动。若只是可重新生成的缓存，可以注册为 `persistent=False`，使其不进入 `state_dict`。

普通 Tensor 属性不会自动随模型移动：

```python
self.mean = torch.tensor([0.2860])  # 不是 Parameter，也不是 Buffer
```

当输入迁移到 GPU 而这个属性仍留在 CPU 时，前向会报设备不一致。Parameter、Buffer 和普通属性的选择，本质上是在声明状态生命周期。

## state_dict 是状态协议

`state_dict()` 返回从模块树收集的参数与持久 Buffer：

```python
model = NormalizeAndClassify()

for key, value in model.state_dict().items():
    print(key, tuple(value.shape))
```

键名由模块路径组成，例如：

```text
mean
std
model.classifier.0.weight
model.classifier.0.bias
model.classifier.3.weight
model.classifier.3.bias
```

`state_dict` 不包含 `forward` 代码和普通 Python 配置。加载时必须先用兼容结构实例化模型，再恢复状态：

```python
restored = NormalizeAndClassify()
result = restored.load_state_dict(model.state_dict())
assert not result.missing_keys
assert not result.unexpected_keys
```

生产代码不应随意用 `strict=False` 忽略所有差异。缺失键与多余键可能代表模型版本不兼容；只有明确执行迁移、微调或部分加载时，才应逐项解释差异。

第 9 篇会把模型、优化器、调度器和训练进度一起组织成可恢复 Checkpoint。

## 设备迁移沿模块树传播

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = NormalizeAndClassify().to(device)
images = torch.rand(8, 1, 28, 28, device=device)
logits = model(images)
```

`model.to(device)` 会迁移已注册的 Parameter 与 Buffer，并原地修改 Module；Tensor 的 `.to()` 则应接住返回值。创建优化器前后移动模型在多数常见场景都可工作，但最清晰的初始化顺序是：

```text
构造模型 → 移动到目标设备 → 构造优化器
```

不要在 `forward` 内调用 `.to(device)`。模型不应该猜测全局设备；输入、模型和辅助 Tensor 应由外层训练代码统一放置。

## 参数初始化

PyTorch 各层有默认初始化。需要自定义时，可以通过 `apply` 遍历模块树：

```python
def initialize(module: nn.Module) -> None:
    if isinstance(module, nn.Linear):
        nn.init.kaiming_uniform_(module.weight, nonlinearity="relu")
        if module.bias is not None:
            nn.init.zeros_(module.bias)


model = FashionMLP()
model.apply(initialize)
```

初始化不是越复杂越好。它必须与激活函数、网络深度和训练目标匹配；修改默认值后应记录策略和随机种子。对预训练模型调用全局初始化会破坏已有权重，这是迁移学习中常见事故。

## train 与 eval 模式

`model.train()` 把根模块及所有子模块切换为训练模式，`model.eval()` 等价于 `model.train(False)`。它们主要影响行为依赖模式的层：

- Dropout 在训练时随机丢弃并缩放激活，推理时直接通过。
- BatchNorm 在训练时使用当前批次统计并更新运行状态，推理时使用保存的运行统计。

```python
model = FashionMLP(dropout=0.5)
images = torch.randn(4, 1, 28, 28)

model.train()
train_a = model(images)
train_b = model(images)

model.eval()
with torch.inference_mode():
    eval_a = model(images)
    eval_b = model(images)

assert not torch.equal(train_a, train_b)
assert torch.equal(eval_a, eval_b)
```

训练模式与梯度模式是两套独立状态：`eval()` 不关闭梯度，`inference_mode()` 也不会把 Dropout 自动切成推理行为。验证和推理通常需要二者配合。

## Module 与 functional API

带可学习状态的层通常使用 `nn.Module`：

```python
self.linear = nn.Linear(128, 10)
```

无状态函数可以使用 `torch.nn.functional`：

```python
import torch.nn.functional as F

x = F.relu(x)
```

两者不是竞争关系。`nn.ReLU()` 便于放进 Sequential 和模块遍历，`F.relu()` 适合在复杂 `forward` 中直接表达运算。关键是 Parameter 和 Buffer 必须注册，不能藏在未追踪的闭包或容器中。

## 常见误区

- **直接调用 `forward`**：会绕过 Module 调用协议与 Hook。
- **普通列表会注册层**：应使用 ModuleList、ModuleDict 或 Sequential。
- **所有模型 Tensor 都是 Parameter**：不训练但需要持久化和迁移的状态应是 Buffer。
- **`eval()` 会关闭 Autograd**：模式与梯度记录相互独立。
- **`state_dict` 保存完整 Python 模型**：它只保存状态，加载端仍需要模型定义与配置。
- **`strict=False` 是通用兼容方案**：它可能静默跳过真正缺失的权重。
