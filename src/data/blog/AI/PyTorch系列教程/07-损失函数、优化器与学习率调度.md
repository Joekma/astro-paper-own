## 本篇要解决的问题

分类模型为什么应直接把 logits 交给 `CrossEntropyLoss`，而不是先做 Softmax？优化器到底保存了哪些状态？梯度裁剪、梯度累积和学习率调度分别发生在一次训练 step 的哪个位置？

一次更新可以压缩成：

```text
清梯度 → forward → loss → backward → 可选裁剪 → optimizer.step
                                           ↓
                                  scheduler 按约定更新
```

顺序错误不一定立即报错，却会改变训练语义。

### 前置知识

掌握 Autograd、`nn.Module`、FashionMNIST 的 `[B,1,28,28]` 输入和 `[B]` 标签契约。

## logits 不是概率

FashionMLP 最后一层输出十个不受约束的实数：

```text
logits: [B, 10]
target: [B], dtype=int64, value in [0, 9]
```

`CrossEntropyLoss` 内部组合了 `LogSoftmax` 与负对数似然，以更稳定的方式计算：

```python
import torch
import torch.nn as nn

criterion = nn.CrossEntropyLoss()

logits = torch.tensor(
    [[2.0, 0.5, -1.0], [0.1, 1.2, 0.3]],
    requires_grad=True,
)
targets = torch.tensor([0, 1], dtype=torch.int64)
loss = criterion(logits, targets)
loss.backward()
```

不要先调用 Softmax：

```python
# 错误：CrossEntropyLoss 期望原始 logits
probabilities = torch.softmax(logits, dim=1)
wrong_loss = criterion(probabilities, targets)
```

错误写法通常仍能运行，但数值稳定性、梯度和损失含义都改变。只有展示概率或按分布采样时才显式 Softmax：

```python
probabilities = torch.softmax(logits, dim=1)
predictions = logits.argmax(dim=1)
```

`argmax(logits)` 与 `argmax(softmax(logits))` 相同，推理分类不必先算概率。

## reduction 决定梯度尺度

多数损失默认 `reduction="mean"`，把 batch 内样本损失取平均：

```python
per_sample = nn.CrossEntropyLoss(reduction="none")(logits, targets)
mean_loss = per_sample.mean()
sum_loss = per_sample.sum()
```

- `none` 保留每个样本损失，适合加权、挖掘难样本和诊断。
- `mean` 让梯度尺度相对不随 batch size 线性增长。
- `sum` 让梯度规模随样本数变化，适合某些明确的统计定义。

记录 epoch loss 时，不能简单平均每个 batch 的均值，因为最后一个 batch 可能更小：

```python
loss_sum += loss.item() * images.size(0)
sample_count += images.size(0)
epoch_loss = loss_sum / sample_count
```

## 根据任务选择损失

常见对应关系：

| 任务 | 模型输出 | 目标 | 常用损失 |
| --- | --- | --- | --- |
| 单标签多分类 | `[B,C]` logits | `[B]` int64 类别索引 | `CrossEntropyLoss` |
| 二分类或多标签 | `[B,C]` logits | `[B,C]` 浮点 0/1 | `BCEWithLogitsLoss` |
| 回归 | 与目标同 Shape | 浮点连续值 | `MSELoss`、`L1Loss`、`HuberLoss` |

`BCEWithLogitsLoss` 同样已包含稳定的 Sigmoid 计算，不应提前调用 `sigmoid`。损失函数的名字不是选择依据，输出与目标契约才是。

类别不平衡时，`CrossEntropyLoss(weight=...)` 的权重按类别索引作用；`BCEWithLogitsLoss(pos_weight=...)` 调整正例项。加权会改变优化目标，不能只看加权 loss，还要在原始验证分布上报告指标。

## 优化器持有参数引用和状态

```python
model = nn.Sequential(
    nn.Flatten(),
    nn.Linear(28 * 28, 256),
    nn.ReLU(),
    nn.Linear(256, 10),
)

optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,
    weight_decay=1e-2,
)
```

优化器并不执行反向传播。`loss.backward()` 把梯度写入 Parameter 的 `.grad`，`optimizer.step()` 读取它们并更新参数。AdamW 还为各参数维护一阶、二阶动量等状态，因此恢复训练不能只加载模型权重。

构建优化器后用新 Module 替换模型层，会让优化器继续引用旧 Parameter。改变结构后应重新构造优化器，或明确更新 parameter groups。

## SGD 与 AdamW

两者没有对所有任务都成立的优劣关系：

```python
sgd = torch.optim.SGD(
    model.parameters(),
    lr=0.1,
    momentum=0.9,
    weight_decay=1e-4,
)

adamw = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,
    weight_decay=1e-2,
)
```

- SGD 更新规则直接、状态较少，在视觉任务中配合动量和良好调度常有强基线。
- AdamW 为每个参数自适应缩放更新，通常更容易获得可用初始结果，也是 Transformer 训练常见选择。
- AdamW 把权重衰减与梯度更新解耦，不等同于 Adam 中简单的 L2 正则项。

学习率、batch size、初始化、归一化和调度彼此耦合。更换优化器时不能只保留原学习率并比较一次结果。

## 标准参数更新顺序

```python
model.train()

for images, targets in train_loader:
    images = images.to(device)
    targets = targets.to(device)

    optimizer.zero_grad(set_to_none=True)
    logits = model(images)
    loss = criterion(logits, targets)
    loss.backward()
    optimizer.step()
```

清梯度可以放在循环末尾，但放在前向之前更容易阅读：它清楚声明本次 step 从空梯度开始。异常导致某一步提前退出时，也不容易把半成品梯度带入下一轮。

更新之后再读取 `.grad` 仍能看到本轮梯度，直到下次清理；这不代表参数更新还未发生。

## 梯度裁剪

梯度范数异常大时可在 `backward` 后、`step` 前裁剪：

```python
loss.backward()
total_norm = torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    max_norm=1.0,
    error_if_nonfinite=True,
)
optimizer.step()
```

裁剪是限制单次更新的安全措施，不是修复所有 NaN 的工具。若 loss 计算已经溢出、数据含非有限值或学习率错误，应该先找根因。记录裁剪前范数和触发频率，比只写一个固定阈值更有诊断价值。

混合精度下必须先用 GradScaler 解除缩放，再裁剪；第 12 篇会给出完整顺序。

## 梯度累积

显存只能容纳小 batch 时，可以连续处理多个 micro-batch，再更新一次：

```python
accumulation_steps = 4
optimizer.zero_grad(set_to_none=True)

for step, (images, targets) in enumerate(train_loader, start=1):
    images = images.to(device)
    targets = targets.to(device)

    logits = model(images)
    loss = criterion(logits, targets) / accumulation_steps
    loss.backward()

    if step % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad(set_to_none=True)
```

除以累积步数使平均梯度尺度接近大 batch。还要处理 epoch 末不足 `accumulation_steps` 的尾部，否则最后几个 batch 不会更新。BatchNorm、Dropout 随机性和优化器更新频率意味着梯度累积并不在所有方面等价于一次真实大 batch。

## 学习率调度

调度器改变各 parameter group 的学习率。按 epoch 调用的余弦示例：

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=20,
)

for epoch in range(20):
    train_one_epoch(...)
    validate(...)
    scheduler.step()
```

不同调度器的 step 单位不同：

- `CosineAnnealingLR` 可以按 epoch 或按 batch 使用，但 `T_max` 必须与调用次数一致。
- `OneCycleLR` 通常每个 optimizer step 后调用一次。
- `ReduceLROnPlateau` 在验证后接收监控指标，如 `scheduler.step(val_loss)`。

不要只复制 `scheduler.step()` 的位置。先写清楚调度轴是 optimizer update、epoch 还是验证事件，再设置总步数。

记录实际学习率：

```python
learning_rates = [group["lr"] for group in optimizer.param_groups]
print(learning_rates)
```

## 参数分组

可以为不同参数设置不同超参数，例如不给 bias 和一维归一化参数应用权重衰减：

```python
decay = []
no_decay = []

for name, parameter in model.named_parameters():
    if not parameter.requires_grad:
        continue
    if parameter.ndim == 1 or name.endswith(".bias"):
        no_decay.append(parameter)
    else:
        decay.append(parameter)

optimizer = torch.optim.AdamW(
    [
        {"params": decay, "weight_decay": 1e-2},
        {"params": no_decay, "weight_decay": 0.0},
    ],
    lr=3e-4,
)
```

参数分组应按明确规则生成，并检查没有遗漏或重复。复杂项目可比较所有 Parameter 的 `id`，保证每个可训练参数只进入一个 group。

## 常见误区

- **先 Softmax 再交叉熵**：CrossEntropyLoss 要求原始 logits。
- **优化器负责计算梯度**：梯度来自 `backward()`，优化器只消费梯度和自身状态。
- **忘记清梯度**：会把不同更新步意外累积。
- **调度器都在 epoch 末调用**：调用频率取决于调度器定义。
- **裁剪能修复 NaN**：它只能约束仍然有限的梯度规模。
- **梯度累积完全等价于大 batch**：状态层和随机操作可能不同。

2. 梯度裁剪应位于一次 step 的哪个位置？
3. 为什么恢复 AdamW 训练时还要加载优化器状态？

<details>
<summary>查看答案</summary>

1. 它内部已经用数值稳定方式组合 LogSoftmax 和 NLL，提前 Softmax 会改变输入与梯度语义。
2. `backward` 产生梯度之后、`optimizer.step` 消费梯度之前；AMP 时还要先解除缩放。
3. AdamW 的动量、二阶矩和步数都会影响下一次更新，只恢复参数会改变训练轨迹。
