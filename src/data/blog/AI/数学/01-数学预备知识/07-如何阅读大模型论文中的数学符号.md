## 公式不是需要一次看懂的整句话

论文公式把大量定义压缩在少量符号中。读不懂时，问题往往不是“数学太难”，而是对象、Shape、索引和运算同时出现。有效的方法不是从左到右反复默读，而是逐层拆开。

本系列采用五步法：

1. 找出公式的输入和输出；
2. 标注每个对象是标量、向量还是矩阵；
3. 写出 Shape 和索引含义；
4. 按运算顺序展开；
5. 补齐公式依赖的假设与省略项。

## 第一步：先读公式附近的定义

符号没有跨论文统一的含义。$N$ 可能是样本数、序列长度或节点数；$d$ 可能是输入维度或头维度；$W$ 通常是权重，但也可能表示图的边权矩阵。

先寻找类似以下语句：

$$
\mathbf{X}\in\mathbb{R}^{T\times C}
$$

它说明 $\mathbf{X}$ 是一个 $T$ 行、$C$ 列的实矩阵。结合正文，$T$ 可能是 Token 数，$C$ 是模型维度。若批次轴被省略，实际实现可能使用 `[B,T,C]`。

上标也不一定表示乘方。$\mathbf{K}^{\mathsf T}$ 是转置，$x^{(l)}$ 常表示第 $l$ 层，$x^2$ 才通常表示平方。

## 第二步：用 Shape 检查公式

以缩放点积注意力为例：

$$
\operatorname{Attention}(\mathbf{Q},\mathbf{K},\mathbf{V})
=
\operatorname{softmax}
\left(
\frac{\mathbf{Q}\mathbf{K}^{\mathsf T}}{\sqrt{d_k}}
\right)
\mathbf{V}
$$

先忽略含义，只写 Shape。设：

$$
\mathbf{Q}\in\mathbb{R}^{T_q\times d_k},
\quad
\mathbf{K}\in\mathbb{R}^{T_k\times d_k},
\quad
\mathbf{V}\in\mathbb{R}^{T_k\times d_v}
$$

则：

```text
Q @ Kᵀ          [Tq,dk] @ [dk,Tk] → [Tq,Tk]
softmax(...)    [Tq,Tk] → [Tq,Tk]
weights @ V     [Tq,Tk] @ [Tk,dv] → [Tq,dv]
```

仅靠 Shape 就能发现很多抄写错误：若 $\mathbf{K}$ 没有转置，中间维度通常无法相乘。

## 第三步：把矩阵式展开成元素式

矩阵 $\mathbf{Q}\mathbf{K}^{\mathsf T}$ 的元素为：

$$
s_{ij}
=
\sum_{r=1}^{d_k}Q_{ir}K_{jr}
$$

$i$ 选择一个 Query 位置，$j$ 选择一个 Key 位置，$r$ 沿特征轴聚合。元素式解释了矩阵式隐藏的循环，也说明输出为什么有 $T_q\times T_k$ 个分数。

Softmax 还必须说明沿哪个轴计算：

$$
a_{ij}
=
\frac{\exp(s_{ij}/\sqrt{d_k})}
{\sum_{m=1}^{T_k}\exp(s_{im}/\sqrt{d_k})}
$$

对固定的 $i$，分母遍历全部 Key，所以每一行之和为 1。论文若只写 `softmax`，轴往往由上下文和 Shape 隐含给出。

## 第四步：寻找省略的条件

公式可能为了突出主线而省略：

- Batch 与多头轴；
- bias、mask、dropout 或归一化；
- 参数是否共享；
- 训练与推理时的不同；
- 数值稳定实现；
- 变量独立、可微或归一化等假设。

“论文没有写在这一行”不等于“实现中不存在”。应结合算法框、图注、附录和代码判断。

## 一套可复用的阅读记录

遇到新公式时，可以填写：

```text
输出：
输入对象与 Shape：
参数：
逐步运算：
聚合/归一化轴：
成立条件：
被省略的实现细节：
我能手算的最小例子：
```

如果仍无法填写，优先回查符号定义，而不是立即搜索整条公式的“通俗解释”。别人的解释可能采用不同 Shape 或约定。

## 常见符号约定

| 符号              | 常见含义       | 需要确认             |
| ----------------- | -------------- | -------------------- |
| $\mathbf{x}$      | 向量           | 行向量还是列向量     |
| $\mathbf{X}$      | 矩阵或批数据   | 每个轴的含义         |
| $\theta$          | 参数集合       | 包含哪些参数         |
| $\nabla_\theta L$ | 对参数的梯度   | Shape 是否与参数一致 |
| $\mathbb{E}[X]$   | 期望           | 对哪个分布取期望     |
| $p(x\mid y)$      | 条件概率或密度 | 变量是离散还是连续   |
| $\propto$         | 成比例         | 省略了哪个归一化常数 |
| $\odot$           | 逐元素乘法     | 是否发生广播         |

## 常见误区

- 认为相同字母在所有论文中含义相同。
- 跳过 Shape，直接凭术语猜运算。
- 把元素乘法、点积和矩阵乘法混为一谈。
- 看到等号就认为两边是逐元素相等，而不检查对象类型。
- 只读主公式，不读它前后的定义、假设和下标说明。

## 本篇自检

1. 为什么读公式时应先写 Shape？
2. Attention 中 Softmax 为什么按 Key 轴计算？
3. 论文公式没有 Batch 轴，是否说明实现一次只能处理一个样本？

<details>

1. Shape 能确定运算是否合法，并暴露转置、聚合轴和输出结构。
2. 每个 Query 都需要对全部 Key 得到一份独立的归一化权重。
3. 不是。论文常省略不影响核心关系的 Batch 轴，实现通常会补上。

## 小结

阅读公式的关键不是背符号，而是恢复被压缩的计算契约：对象、Shape、索引、运算顺序和假设。下一模块将从向量的几何直觉开始系统学习线性代数。
