## 一、这篇文章要解决什么问题

当 Node.js 跳出浏览器，**文件操作**就成了最高频的需求：

- 写个脚本读取 `config.json`，把里面的数据库配置加载进来；
- 把后端接口的响应写成本地日志文件；
- 批量重命名、批量压缩、批量转码（图片/视频/文档）；
- 写个静态博客生成器，把 Markdown 编译成 HTML；
- 上传文件到对象存储前先读出内容。

这些事情，全靠 Node.js 内置的 `fs`（file system）模块。这一篇会从最基础的"读一个文件"讲到"用流处理 GB 级大文件"，让你彻底掌握 `fs`。

![Node.js fs 模块连接脚本与文件系统，并提供同步、异步和流式处理三类能力](./images/nodejs-fs-file-system-api-flow-figure-01.png)

## 二、先用一句话讲清楚

**`fs` 模块是 Node.js 用来操作本地文件系统的内置模块。它有三套 API：同步（`fs.readFileSync`）、回调风格异步（`fs.readFile`）、Promise 化异步（`fs.promises.readFile`），新版代码统一用 Promise 风格。**

## 三、官方文档是怎么说的

[Node.js 中文文档 - File system](https://nodejs.cn/api/fs.html) 开篇：

> `fs` 模块提供了一种 API，用于以一种模仿标准 POSIX 函数的方式与文件系统进行交互。
>
> 所有文件系统操作都具有**同步**、**回调**和 **promise-based** 三种形式，并且可以使用 CommonJS 回调和 Promise 回调进行访问。

补充理解（不属于官方文档原文）：

- **POSIX 风格**：参数顺序一般是 `(path, options, callback)`，对应 Linux 系统的 `open`、`read`、`write` 等系统调用。
- **Promise API** 在 v10 之后逐步完善，v14 之后稳定，**新代码应该默认用 `fs.promises`**。

## 四、换成人话怎么理解

把 `fs` 想象成**电脑里的文件管家**，他帮你做这些事：

- **读**：把文件里的内容拿出来——"管家，把《hello.txt》给我读一下"。
- **写**：把一段内容写到文件里——"管家，把这段话写进《note.txt》"。
- **看**：看看文件存不存在、有多大、什么时候改的——"管家，看看《data.json》多大"。
- **改**：改名字、换位置——"管家，把《a.txt》改名为《b.txt》"。
- **删**：把文件删掉——"管家，把《tmp.log》删了"。
- **建文件夹/遍历文件夹**：建一个目录、列出目录里所有文件——"管家，建一个『/photos/2026』目录，列出里面所有照片"。

管家提供三种工作方式：

1. **同步**：管家说"你站着别动，我去把文件读完再回来告诉你"——**会卡住你后面的代码**。
2. **回调异步**：管家说"我先去读，你该干嘛干嘛，读完了我喊你"——**不卡你**。
3. **Promise 异步**：管家说"我先去读，给你个手机号（Promise），读完了给你发短信（resolve）"——**最现代的写法**。

## 五、最小可运行示例

> 本节用 **Promise 风格**（`fs/promises`），是 Node.js 14+ 的官方推荐写法。如果项目是 ESM，用 `import { readFile } from 'node:fs/promises'`；CJS 用 `const { readFile } = require('node:fs/promises')`。
>
> 提示：`node:fs/promises` 带 `node:` 前缀是**官方推荐**的写法，可以和用户安装的 `fs` 包区分开。

### 5.1 读取文件

```js
// read.mjs
import { readFile } from 'node:fs/promises';

const content = await readFile('hello.txt', 'utf8');
console.log(content);
```

**逐行解释：**

- `import { readFile } from 'node:fs/promises'`：从内置的 fs Promise 子模块导入 `readFile`。
- `await readFile('hello.txt', 'utf8')`：**异步**读取文件，第二个参数 `'utf8'` 告诉 Node "以文本方式读取并解码成字符串"。如果不传，拿到的是 `Buffer`（原始字节数组，下一篇讲）。
- `await`：必须在 `async` 函数或 ES Module 顶层使用（这里的 `read.mjs` 是 ESM，顶层可以用 await）。

### 5.2 写入文件

```js
// write.mjs
import { writeFile } from 'node:fs/promises';

// 覆盖写入（不存在则创建，存在则覆盖）
await writeFile('note.txt', '这是我的第一行笔记\n', 'utf8');

// 追加写入
import { appendFile } from 'node:fs/promises';
await appendFile('note.txt', '第二行内容\n', 'utf8');
```

**关键点：**

- `writeFile` 默认**覆盖**已有文件，**不是**追加。
- `appendFile` 专门用于追加。
- 写入可以用 `flags` 选项控制行为，如 `appendFile` 内部就是 `writeFile(p, d, { flag: 'a' })`。

### 5.3 读取 JSON 配置

```js
// config.json
{
  "port": 3000,
  "db": { "host": "localhost", "user": "root" }
}
```

```js
// load-config.mjs
import { readFile } from 'node:fs/promises';

const text = await readFile('config.json', 'utf8');
const config = JSON.parse(text);
console.log(config.port);          // 3000
console.log(config.db.host);      // localhost
```

### 5.4 文件元信息

```js
// stat.mjs
import { stat } from 'node:fs/promises';

const info = await stat('hello.txt');
console.log(info.isFile());    // 是否是文件
console.log(info.isDirectory()); // 是否是目录
console.log(info.size);         // 字节数
console.log(info.mtime);        // 最后修改时间
```

### 5.5 目录操作

```js
// dir.mjs
import { mkdir, readdir, rm } from 'node:fs/promises';

// 递归创建目录（类似 mkdir -p）
await mkdir('logs/2026/06', { recursive: true });

// 列出目录内容
const files = await readdir('logs/2026/06');
console.log(files);

// 删除目录（recursive 必须加，否则只能删空目录）
await rm('logs/2026/06', { recursive: true, force: true });
```

### 5.6 批量重命名（实战小例子）

```js
// rename.mjs
import { readdir, rename } from 'node:fs/promises';
import { join } from 'node:path';

const dir = 'photos';
const files = await readdir(dir);

for (const name of files) {
  // 把 IMG_001.jpg 改成 photo-001.jpg
  const newName = name.replace(/^IMG_/, 'photo-');
  if (newName !== name) {
    await rename(join(dir, name), join(dir, newName));
    console.log(`重命名：${name} -> ${newName}`);
  }
}
```

### 5.7 大文件：必须用流

`readFile` 会**一次性**把整个文件读进内存。读 100 MB 还行，读 10 GB 就 OOM 了。

```js
// copy-big-file.mjs
import { createReadStream, createWriteStream } from 'node:fs';
import { promisify } from 'node:util';
import { pipeline } from 'node:stream/promises';

const src = 'big-video.mp4';
const dest = 'big-video-copy.mp4';

await pipeline(
  createReadStream(src),
  createWriteStream(dest)
);
console.log('拷贝完成');
```

下一篇（Stream）会详细讲。先记住：**小文件用 `readFile`/`writeFile`；大文件用 stream。**

## 六、实际项目中怎么用

| 场景 | 用到的 API | 注意事项 |
| ---- | ---------- | -------- |
| **读取配置文件**（`config.json`、`.env`） | `readFile` | 加 `try/catch`，文件不存在要给默认值 |
| **写日志** | `appendFile` | 高并发场景下用 `fs.createWriteStream`（流） |
| **上传文件到 OSS** | `createReadStream` | 配合 SDK 的 `putObject` 流式上传 |
| **批量处理图片/视频** | `readdir` + `child_process` | 用 ffmpeg/imagemin 的子进程 |
| **静态博客生成器** | `readdir`、`readFile`、`writeFile` | 把 Markdown 编译成 HTML |
| **CSV 解析与导出** | `createReadStream` | 一行一行处理，不爆内存 |
| **备份脚本** | `createReadStream` + `createWriteStream` | 用 `pipeline` 安全拷贝 |
| **临时文件** | `tmpdir` + `mkdtemp` | 用 `node:os` 的 `tmpdir()`，不要硬编码路径 |

补充理解（不在官方文档原文）—— 高并发日志写入的常见做法：

```js
// logger.mjs
import { createWriteStream } from 'node:fs';
import { mkdir } from 'node:fs/promises';
import { dirname } from 'node:path';

const logPath = 'logs/app.log';
await mkdir(dirname(logPath), { recursive: true });

// O_APPEND 追加；O_CREAT 不存在则创建
const stream = createWriteStream(logPath, { flags: 'a' });

export function log(message) {
  stream.write(`[${new Date().toISOString()}] ${message}\n`);
}
```

## 七、常见误区

### 误区 1：忘记指定 `'utf8'`，拿到 `Buffer`

- **错在哪里**：`await readFile('hello.txt')` 拿到的不是字符串，是 `Buffer`。
- **为什么会错**：`fs` 的 API 默认返回**原始字节数组**（`Buffer`），需要显式传编码。
- **正确写法**：
  ```js
  // 文本
  const text = await readFile('hello.txt', 'utf8');
  
  // 二进制（图片、视频）
  const buf = await readFile('photo.png'); // 不传编码，拿到 Buffer
  ```

### 误区 2：把所有文件操作都用同步 API

- **错在哪里**：写服务端代码时也用 `readFileSync`。
- **为什么会错**：同步 API 会**阻塞事件循环**，所有其他请求都等着。
- **正确写法**：服务端代码一律用 Promise / 异步；同步 API 只在启动初始化、CLI 工具等"一锤子买卖"场景下用。

### 误区 3：不处理"文件不存在"异常

- **错在哪里**：`const data = await readFile('maybe-missing.json', 'utf8');` 启动就崩。
- **为什么会错**：文件不存在会抛 `ENOENT` 异常。
- **正确写法**：
  ```js
  try {
    const data = await readFile('maybe-missing.json', 'utf8');
    return JSON.parse(data);
  } catch (err) {
    if (err.code === 'ENOENT') return null; // 不存在时给默认值
    throw err;
  }
  ```

### 误区 4：路径用 `+` 字符串拼接

- **错在哪里**：`const p = dir + '/' + name`。
- **为什么会错**：Windows 用 `\`，Mac/Linux 用 `/`，硬编码会跨平台翻车。
- **正确写法**：用 `path.join`（下一篇细讲）。

### 误区 5：`rmdir` 删非空目录

- **错在哪里**：`await rmdir('myDir')` 报错 `ENOTEMPTY`。
- **为什么会错**：Node.js 老 API 的 `rmdir` 默认只能删**空目录**。
- **正确写法**：用 `rm(p, { recursive: true, force: true })`。

## 八、和相似概念的区别

| 概念 | 是什么 | 关键差异 |
| ---- | ------ | -------- |
| **`fs` (同步)** | `fs.readFileSync` | 会**阻塞**事件循环，**仅适合启动初始化和 CLI** |
| **`fs` (回调)** | `fs.readFile(cb)` | 经典异步写法，**已不推荐**（容易回调地狱） |
| **`fs/promises`** | `fs.promises.readFile` | **官方推荐**的现代异步写法 |
| **`node:fs` vs 第三方库** | `fs-extra`、`graceful-fs` | 第三方库提供 `ensureDir`、`copy` 等便利 API；底层仍是 `fs` |
| **浏览器** | `FileReader`、`fetch('/xx')` + `File` | 浏览器只能在用户主动上传时拿到文件对象，**不能直接读本地任意文件** |

## 九、小结

1. `fs` 提供**三种风格的 API**：同步、回调、Promise。**新代码统一用 `fs/promises`**。
2. **小文件**用 `readFile` / `writeFile` / `appendFile`；**大文件**用 `createReadStream` / `createWriteStream`（下一篇详解）。
3. 文本读取要传 `'utf8'`；二进制不传编码，拿到 `Buffer`。
4. 永远 **`try/catch`** 包裹 `fs` 调用，并处理 `ENOENT`（不存在）、`EACCES`（无权限）等常见错误码。
5. 路径**不要硬编码 `/` 或 `\`**，用 `path.join` 跨平台拼接；目录操作记住 `mkdir({ recursive: true })` 和 `rm({ recursive: true })`。
