## 概述

TCP（Transmission Control Protocol，传输控制协议）是 Internet 上最重要的协议之一，提供面向连接、可靠传输、流控制的服务。

## TCP 核心特性

| 特性 | 说明 |
|------|------|
| **面向连接** | 通过三次握手建立连接，四次挥手关闭 |
| **可靠传输** | 确认机制、超时重传、序列号 |
| **流量控制** | 滑动窗口机制 |
| **拥塞控制** | 防止网络拥塞 |
| **全双工** | 双向数据传输 |
| **字节流** | 无边界的数据流 |


| 字段 | 长度 | 说明 |
|------|------|------|
| **源端口** | 16 位 | 发送端端口号 |

| **确认号** | 32 位 | 期望收到的下一个字节 |
| **数据偏移** | 4 位 | TCP 头部长度 |
| **标志位** | 9 位 | URG/ACK/PSH/RST/SYN/FIN |
| **窗口大小** | 16 位 | 接收窗口大小 |

### TCP 标志位

| 标志 | 说明 | 用途 |
|------|------|------|
| **SYN** | 同步位 | 建立连接 |
| **ACK** | 确认位 | 确认收到 |
| **FIN** | 结束位 | 关闭连接 |
| **RST** | 复位位 | 异常断开 |
| **PSH** | 推送位 | 立即交付 |
| **URG** | 紧急位 | 紧急数据 |

## TCP 三次握手

### 为什么需要三次握手

```
客户端                      服务端
    │                          │
    │───── SYN=1, seq=x ──────▶│  客户端发送连接请求
    │                          │
    │◀── SYN=1, ACK=1,        │  服务端返回确认
    │    seq=y, ack=x+1 ──────│
    │                          │
    │───── ACK=1,              │  客户端确认
    │    seq=x+1, ack=y+1 ────▶│
    │                          │
    │      连接建立成功！       │
```

### 三次握手目的

1. **确认双方接收能力**：双方都能确认对方能收能发
2. **同步序列号**：交换初始序列号（ISN）
3. **协商参数**：如 MSS、窗口大小

### 序列号与确认号

```python
# 序列号（Sequence Number）
- 初始序列号（ISN）是随机生成的
- 每个字节数据都有对应的序列号
- 用于数据排序和重复检测

# 确认号（Acknowledgment Number）
- 表示"已成功接收，最后一个字节是 ack-1"
- 期望收到的下一个字节编号

# 示例
客户端发送 seq=100, data=100字节
服务端返回 ack=200（已成功接收前199字节）
```

### 握手过程详解

```bash
# 第一次握手
客户端 ──▶ SYN=1, seq=x, flags=SYN
        ──▶ 服务端知道客户端能发送

# 第二次握手
客户端 ◀── SYN=1, ACK=1, seq=y, ack=x+1
       ◀── 服务端知道服务端能收能发

# 第三次握手
客户端 ──▶ ACK=1, seq=x+1, ack=y+1
        ──▶ 客户端知道服务端能接收
```

### 半连接与全连接

```python
# 半连接状态（SYN_RECV）
服务端收到 SYN 后进入半连接
等待客户端的 ACK

# 全连接队列（Accept Queue）
三次握手完成后进入全连接
等待应用调用 accept()

# 查看半连接数量
netstat -an | grep SYN_RECV

# 调整队列大小
tcp_max_syn_backlog = 4096
```

## TCP 四次挥手

### 为什么需要四次挥手

```
客户端                      服务端
    │                          │
    │───── FIN=1, seq=u ──────▶│  客户端请求关闭
    │◀── ACK=1, ack=u+1 ───────│  服务端确认
    │     （客户端等待）        │
    │                          │
    │    （服务端处理剩余数据）  │
    │                          │
    │◀── FIN=1, seq=w ─────────│  服务端请求关闭
    │───── ACK=1, ack=w+1 ────▶│  客户端确认
    │     （等待 2MSL）         │
    │                          │
    │      连接关闭成功         │
```

### 为什么 TIME_WAIT 是 2MSL

```python
# MSL（Maximum Segment Lifetime）
- 一个报文的最大生存时间，通常 60 秒
- 确保最后的 ACK 能被对方收到
- 如果 ACK 丢失，对端会重发 FIN

# 2MSL 的作用
1. 可靠的终止 TCP 连接
2. 让旧连接的数据在网络中消失
3. 避免旧连接的数据影响新连接
```

### 连接状态转换

```bash
# 客户端状态变化
CLOSED ──▶ SYN_SENT ──▶ ESTABLISHED ──▶ FIN_WAIT_1
                                                      │
                                              ◀── ACK ─┘
                                              FIN_WAIT_2
                                                      │
                                              ◀── FIN ─┘
                                                  TIME_WAIT
                                                      │
                                              ◀── 2MSL ─┘
                                                  CLOSED

# 服务端状态变化
CLOSED ──▶ LISTEN ──▶ SYN_RECV ──▶ ESTABLISHED ──▶ CLOSE_WAIT
                                                           │
                                                    ◀── FIN ─┘
                                                    LAST_ACK
                                                           │
                                                    ◀── ACK ─┘
                                                    CLOSED
```

### 常见问题

```python
# 问题：服务器上大量 CLOSE_WAIT
# 原因：应用没有正确关闭连接
# 解决：确保代码中关闭 socket

# 问题：大量 TIME_WAIT
# 原因：频繁创建关闭短连接
# 解决：使用长连接、调整 TIME_WAIT 时间

# 问题：连接无法建立（RST）
# 原因：端口未监听、服务未启动
# 解决：检查服务状态
```

## TCP 可靠传输机制

### 确认机制

```python
# ACK 确认
发送方 ──▶ 数据 seq=100, len=100 ──▶ 接收方
       ◀── ACK ack=200 ───────────────┘

# 累计确认
# 收到 seq=100-199 后 ack=200
# 再收到 seq=200-299 后 ack=300
```

### 超时重传

```python
# RTO（Retransmission Timeout）
- 动态计算，根据 RTT 变化
- 公式：RTO = RTT + 4 * RTTVAR

# 重传触发
1. 超时未收到 ACK
2. 收到 3 个重复 ACK（快重传）

# 指数退避
第一次重传：等待 1 * RTO
第二次重传：等待 2 * RTO
第三次重传：等待 4 * RTO
```

### 序列号作用

```python
# 序列号用途
1. 数据字节编号（从 ISN 开始）
2. 数据排序（处理乱序）
3. 重复检测（丢弃重复数据）
4. 连接标识（跟踪连接）

# 示例
ISN = 1000
发送 500 字节数据：seq=1000-1499
接收方确认：ack=1500
```

### 流量控制

```python
# 滑动窗口
┌─────────────┬──────────────────────────┬─────────────┐
│  已发送已确认 │        可发送            │   不能发送   │
│  (发送窗口外) │     (发送窗口内)         │  (窗口外)    │
└─────────────┴──────────────────────────┴─────────────┘
   ↑                          ↑                    ↑
  SND.UNA                  SND.NXT               SND.UNA+SND.WND
```

### 窗口大小字段

```python
# rwnd（接收窗口）
- 接收方告诉发送方自己能接收多少数据
- 防止发送方发送过快导致缓冲区溢出
- 通过 ACK 中的 window 字段传递

# 零窗口
当接收方缓冲区满时，window=0
发送方停止发送数据
定期发送零窗口探测（Zero Window Probe）
```

## TCP 选项

### 常见选项

| 选项 | 长度 | 说明 |
|------|------|------|
| **MSS** | 4 | 最大报文段长度 |
| **窗口扩大** | 3 | 窗口大小扩大因子 |
| **SACK** | 可变 | 选择性确认 |
| **时间戳** | 10 | RTTM 和 PAWS |

### MSS 选项

```bash
# MSS（Maximum Segment Size）
# 通告自己能接收的最大报文段
# 默认 1460 字节（1500 - 20(IP) - 20(TCP)）

# 路径 MTU 发现
# TCP 会根据路径 MTU 自动调整 MSS
```

### 窗口扩大选项

```python
# 窗口字段只有 16 位，最大 65535 字节
# 使用窗口扩大选项可以支持更大的窗口

# 扩大因子
- 窗口值 = 实际窗口 * 2^扩大因子
- 扩大因子最大 14

# 示例
接收方通告 window=65535, 扩大因子=3
实际窗口 = 65535 * 8 = 524280 字节
```

## 小结

TCP 核心要点：

- **三次握手**：建立可靠连接，交换 ISN
- **四次挥手**：优雅关闭连接，TIME_WAIT 等待
- **可靠传输**：确认机制、超时重传、序列号
- **流量控制**：滑动窗口，防止缓冲区溢出
- **连接状态**：SYN_SENT/ESTABLISHED/FIN_WAIT/TIME_WAIT
