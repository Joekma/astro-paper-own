## 概述

代理服务器作为客户端和服务器之间的中间层，转发请求和响应。根据代理对象的不同，分为正向代理和反向代理。

## 正向代理

### 工作原理

```
┌────────┐                      ┌────────┐                      ┌────────┐
│  客户端  │                      │ 正向代理 │                      │ 目标服务器 │
└───┬────┘                      └───┬────┘                      └───┬────┘
    │                                │                                │
    │──── 请求访问 google.com ──────▶│                                │
    │                                │──── 转发请求到 google.com ───▶│
    │                                │                                │
    │                                │◀─── 返回响应 ──────────────│
    │◀─── 返回响应（伪装后）─────────│                                │
    │                                │                                │
```

### 特点

- **客户端感知**：客户端知道代理存在
- **代理客户端**：为客户端代理请求
- **突破限制**：访问无法直接访问的资源
- **隐藏真实客户端**：服务器不知道真实客户端 IP

### 应用场景

| 场景 | 说明 |
|------|------|
| **科学上网** | 访问国外网站 |
| **访问控制** | 企业内网访问限制 |
| **缓存加速** | 缓存常用资源减少带宽 |
| **日志记录** | 记录用户访问行为 |

### Squid 配置示例

```bash
# /etc/squid/squid.conf

# 端口配置
http_port 3128

# 访问控制
acl localnet src 192.168.1.0/24
acl blocked_site dstdomain .facebook.com

# 拒绝访问
http_access deny blocked_site
http_access allow localnet
http_access deny all

# 缓存配置
cache_dir ufs /var/spool/squid 1000 16 256
maximum_object_size 4096 KB
```

### 使用代理

```bash
# 环境变量
export http_proxy=http://proxy.example.com:3128
export https_proxy=http://proxy.example.com:3128

# curl 使用代理
curl -x http://proxy.example.com:3128 http://example.com

# wget 使用代理
wget -e http_proxy=http://proxy.example.com:3128 http://example.com
```

## 反向代理

### 工作原理

```
┌────────┐                      ┌────────┐                      ┌────────┐
│  客户端  │                      │ 反向代理 │                      │ 后端服务器 │
└───┬────┘                      └───┬────┘                      └───┬────┘
    │                                │                                │
    │──── 请求 example.com ──────────▶│                                │
    │                                │──── 转发请求到内网服务器 ────▶│
    │                                │                                │
    │                                │◀─── 返回响应 ──────────────│
    │◀─── 返回响应 ──────────────────│                                │
    │                                │                                │
```

### 特点

- **客户端无感知**：客户端不知道代理存在
- **代理服务端**：为服务器代理请求
- **负载均衡**：分发请求到多个服务器
- **隐藏真实服务器**：客户端不知道真实服务器 IP

### 应用场景

| 场景 | 说明 |
|------|------|
| **负载均衡** | 分配请求到多台服务器 |
| **SSL 终端** | HTTPS 解密在代理层完成 |
| **缓存静态资源** | 减轻后端服务器压力 |
| **安全防护** | DDoS 防护、防火墙 |

### Nginx 反向代理配置

```nginx
# upstream 配置
upstream backend {
    least_conn;                    # 最少连接算法
    server 192.168.1.10:8080;
    server 192.168.1.11:8080;
    server 192.168.1.12:8080;
}

server {
    listen 80;
    server_name example.com;

    # 反向代理配置
    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;

        # 缓冲设置
        proxy_buffering on;
        proxy_buffer_size 4k;
        proxy_buffers 8 4k;
    }

    # 静态资源缓存
    location /static/ {
        proxy_cache my_cache;
        proxy_cache_valid 200 60m;
        expires 7d;
    }
}
```

### HTTPS 反向代理

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # SSL 配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 正向代理 vs 反向代理

| 对比项 | 正向代理 | 反向代理 |
|--------|----------|----------|
| **代理对象** | 客户端 | 服务器 |
| **客户端感知** | 知道代理存在 | 不知道代理存在 |
| **部署位置** | 客户端侧或专用服务器 | 服务端网络入口 |
| **目标** | 突破访问限制、缓存 | 负载均衡、安全防护 |
| **用途** | 科学上网、访问控制 | Nginx、HAProxy |
| **隐藏** | 隐藏客户端 IP | 隐藏服务端架构 |

## HAProxy 配置

```bash
# /etc/haproxy/haproxy.cfg

frontend http_front
    bind *:80
    mode http
    default_backend web_back

backend web_back
    mode http
    balance roundrobin
    option httpchk /health
    server web1 192.168.1.10:8080 check inter 2000 rise 2 fall 3
    server web2 192.168.1.11:8080 check inter 2000 rise 2 fall 3

listen stats
    bind *:8404
    stats enable
    stats uri /stats
    stats auth admin:password
```

## Python 实现简单代理

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import urlparse
import http.client

class ProxyHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        # 解析 URL
        parsed = urlparse(self.path)

        # 连接目标服务器
        conn = http.client.HTTPConnection(parsed.netloc)

        # 发送请求
        conn.request('GET', parsed.path)
        response = conn.getresponse()

        # 返回响应
        self.send_response(response.status)
        self.send_header('Content-type', response.getheader('Content-type'))
        self.end_headers()
        self.wfile.write(response.read())

        conn.close()

if __name__ == '__main__':
    server = HTTPServer(('0.0.0.0', 8888), ProxyHandler)
    print('代理服务器运行在端口 8888')
    server.serve_forever()
```

## 小结

正向代理和反向代理要点：

- **正向代理**：为客户端代理，突破访问限制
- **反向代理**：为服务端代理，实现负载均衡和安全防护
- **Nginx**：最常用的反向代理和负载均衡服务器
- **HAProxy**：高性能负载均衡器
- **选择依据**：根据业务需求选择合适的代理类型
