> 分布式事务是指在分布式系统中，多个节点参与的事务处理，需要保证 ACID 特性的同时处理网络故障和节点故障。

## CAP 定理

### 三个特性

| 特性 | 说明 |
|------|------|
| **Consistency** | 所有节点看到相同的数据 |
| **Availability** | 每个请求都能得到响应 |
| **Partition tolerance** | 网络分区时系统仍能运行 |

### 选择策略

| 场景 | 选择 | 说明 |
|------|------|------|
| 银行转账 | C + P | 必须保证一致性 |
| 商品查询 | A + P | 高可用更重要 |
| 社交应用 | A + P | 允许短暂不一致 |

分布式系统必须选择 P，通常在 C 和 A 之间权衡。

## BASE 理论

### 核心思想

| 特性 | 说明 |
|------|------|
| **Basically Available** | 基本可用，允许故障降级 |
| **Soft state** | 软状态，数据可以不一致 |
| **Eventually consistent** | 最终一致性 |

### 与 ACID 对比

| ACID | BASE |
|------|------|
| 强一致性 | 弱一致性 |
| 阻塞等待 | 非阻塞 |
| 集中式 | 分布式 |

## 分布式事务解决方案

### 2PC（两阶段提交）

```
阶段一：提交请求
Coordinator → Participants（询问是否可以提交）

阶段二：提交/回滚
Coordinator → Participants（执行提交或回滚）
```

```python
class TwoPhaseCommit:
    def phase1_prepare(self):
        for participant in participants:
            if not participant.prepare():
                self.phase2_rollback()
                return False
        return True

    def phase2_commit(self):
        for participant in participants:
            participant.commit()
```

### TCC（Try-Confirm-Cancel）

```python
class TCCHandler:
    def try_phase(self):
        for action in actions:
            action.try()

    def confirm_phase(self):
        for action in actions:
            action.confirm()

    def cancel_phase(self):
        for action in actions:
            action.cancel()
```

### Saga 模式

```python
class Saga:
    def execute(self):
        for step in self.steps:
            if not step.execute():
                self.compensate()
                return False
        return True

    def compensate(self):
        for step in reversed(self.completed_steps):
            step.rollback()
```

## 分布式锁

### Redis 分布式锁

```python
import redis
import uuid

class DistributedLock:
    def __init__(self, redis_client, lock_name):
        self.redis = redis_client
        self.lock_name = lock_name
        self.lock_value = str(uuid.uuid4())

    def acquire(self):
        return self.redis.set(
            self.lock_name, self.lock_value,
            nx=True, ex=10
        )

    def release(self):
        script = """
        if redis.call('get', KEYS[1]) == ARGV[1] then
            return redis.call('del', KEYS[1])
        end
        """
        return self.redis.eval(script, 1, self.lock_name, self.lock_value)
```

### Zookeeper 分布式锁

```python
from kazoo.client import KazooClient

class ZKLock:
    def __init__(self, hosts):
        self.client = KazooClient(hosts=hosts)
        self.client.start()
        self.lock = None

    def acquire(self, path):
        self.lock = self.client.Lock(path)
        return self.lock.acquire(blocking=True)

    def release(self):
        if self.lock:
            self.lock.release()
```

## 分布式 ID

### Snowflake 算法

```python
import time
import threading

class Snowflake:
    def __init__(self, worker_id=0):
        self.worker_id = worker_id
        self.sequence = 0
        self.last_timestamp = -1
        self.lock = threading.Lock()
        self.epoch = 1577836800000

    def generate_id(self):
        with self.lock:
            timestamp = int(time.time() * 1000)
            if timestamp == self.last_timestamp:
                self.sequence = (self.sequence + 1) & 4095
            else:
                self.sequence = 0
            self.last_timestamp = timestamp
            return ((timestamp - self.epoch) << 22) | (self.worker_id << 12) | self.sequence
```

## 小结

- **CAP 定理**：分布式系统必须选择 P，通常在 C 和 A 之间权衡
- **BASE 理论**：接受最终一致性，保证基本可用
- **2PC**：强一致，但有阻塞问题
- **TCC**：业务可控，但实现复杂
- **分布式锁**：Redis/Zookeeper 实现
