## 概述

当你在使用 Git 与 GitHub 交互时，可能会遇到以下错误信息：

```
Failed to connect to github.com port 443 after 21090 ms: Couldn't connect to server
```

这个错误通常发生在使用 VPN 后，系统端口号与 Git 端口号不一致时。本文将详细讲解如何排查和解决这一问题。

## 问题背景

端口 443 是 HTTPS 协议的默认端口，Git 与 GitHub 的安全连接需要通过这个端口进行。当出现连接失败时，通常有两个主要原因：

| 原因 | 说明 |
|------|------|
| VPN 代理未配置 | 使用 VPN 后，Git 未正确配置代理设置 |
| 代理冲突 | 存在残留的代理配置导致连接失败 |

## 解决方案

### 方法一：VPN 使用环境下的解决方案

当你在使用 VPN 时，需要将 Git 的代理设置指向 VPN 的本地端口。

#### 步骤 1：查看系统端口号

1. 打开「设置」→「网络和 Internet」→「代理」
2. 记录下当前的端口号

#### 步骤 2：设置 Git 代理

```bash
git config --global http.proxy 127.0.0.1:你的端口号
git config --global https.proxy 127.0.0.1:你的端口号
```

**示例**：如果你的端口号是 `7890`，则输入：

```bash
git config --global http.proxy 127.0.0.1:7890
git config --global https.proxy 127.0.0.1:7890
```

#### 步骤 3：验证设置

```bash
git config --global -l
```

检查输出，确认代理设置已正确配置：

```
http.proxy=127.0.0.1:7890
https.proxy=127.0.0.1:7890
```

#### 步骤 4：刷新 DNS 缓存

在执行 `git push` 或 `git pull` 前，建议刷新 DNS 缓存：

```bash
# Windows
ipconfig /flushdns

# macOS
sudo dscacheutil -flushcache

# Linux
sudo systemd-resolve --flush-caches
```

### 方法二：未使用 VPN 时的解决方案

如果你并未使用 VPN，但依然遇到端口 443 连接失败的问题，可能存在残留的代理配置。

#### 取消 Git 代理设置

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

#### 验证取消成功

```bash
git config --global -l
```

确保输出中不再包含代理相关的配置。

#### 刷新 DNS 缓存

```bash
# Windows
ipconfig /flushdns
```

## 常见问题

### Q1：如何查看当前使用的 VPN 端口？

进入「设置」→「网络和 Internet」→「代理」，在「手动代理设置」下可以看到端口号。

### Q2：命令没有报错但还是推送失败？

1. 检查代理端口是否正确
2. 确保 VPN 已连接
3. 尝试重新打开终端窗口

### Q3：如何临时取消代理设置？

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### Q4：可以只针对 GitHub 配置代理吗？

可以，使用以下命令针对特定域名配置：

```bash
git config --global http.https://github.com.proxy 127.0.0.1:7890
git config --global https.https://github.com.proxy 127.0.0.1:7890
```

## 总结

遇到 Git 连接 GitHub 端口 443 错误时，核心在于检查和调整代理设置：

1. **使用 VPN 时**：将 Git 代理指向 VPN 的本地端口
2. **未使用 VPN 时**：清除可能残留的代理配置
3. **通用步骤**：操作完成后刷新 DNS 缓存

掌握这些技巧，可以让你的代码管理更加高效，不再被网络连接问题困扰。
